# Как работает Concept Loom

[Документация](README.md) · [English](../en/how-it-works.md)

Concept Loom — не новая AI-модель и не отдельная учебная программа. Это методика и небольшой локальный MCP-сервер для Codex, Claude Code или OpenCode.

## Простая модель

```text
Вы                  выбираете цель, отвечаете и практикуетесь
AI-клиент           ведёт урок, читает материалы и ищет источники
concept-coach       говорит AI, как организовать обучение
MCP-сервер          проверяет ответы, пишет конспект и готовит схемы
файлы workspace     сохраняют полезный прогресс
```

AI остаётся преподавателем. MCP выполняет только предсказуемые операции.

## Учебный цикл

### 1. Locate — найти исходную точку

AI превращает широкую тему в наблюдаемый результат и ищет границу понимания. «Развернуть маленькое приложение в контейнере и диагностировать ошибки» полезнее, чем «изучить Docker». Короткие проверки показывают, что уже надёжно и где начинается неуверенность.

### 2. Weave — построить маршрут

```text
известная идея → необходимая связь → новая идея → практический результат
```

Вы утверждаете минимальный маршрут до начала урока. Лишние ветви сознательно исключаются.

### 3. Build — построить понимание

Для каждой связи AI объясняет её необходимость, выводит из уже понятного, даёт вам попробовать, проверяет и исправляет слабое место до перехода дальше. Важные идеи дополнительно проверяются свободным объяснением или новой задачей.

## Архитектура

```text
Codex / Claude Code / OpenCode
      разговор · файлы · поиск · UI
                    │ MCP
Concept Loom
      вопросы · конспект · схемы
                    │
Учебная папка
      Markdown · состояние · материалы
```

Общая методика находится в `shared/coaching-reference.md`, а `adapters/` переводит её в формат каждого клиента. `scripts/setup.mjs` устанавливает адаптер без перезаписи существующих настроек.

`src/bridge.mjs` — локальный MCP-процесс Node.js без npm-зависимостей. Он не открывает сетевой порт.

| Инструмент | Назначение |
|---|---|
| `loom_frame_checkpoint` | Подготовить и перемешать вопрос без показа ответа. |
| `loom_assess_checkpoint` | Оценить ответ и вернуть объяснение. |
| `loom_start_notebook` | Создать или открыть Markdown-конспект. |
| `loom_add_note` | Добавить полезное учебное событие. |
| `loom_save_learning_state` | Сохранить маршрут и точку продолжения. |
| `loom_load_learning_state` | Восстановить последнее или выбранное занятие. |
| `loom_show_relation_map` | Вернуть Mermaid-блок прямо в разговор. |
| `loom_show_text_diagram` | Вернуть моноширинную схему для терминала. |

## Проверочные вопросы

`src/checkpoints.mjs` хранит правильные ключи за случайным токеном. Ученик получает вопрос, перемешанные варианты, токен и `I do not know yet`, но не получает правильный ответ и объяснение.

Результат: `accurate`, `needs-repair` или `knowledge-gap`. Токен действует до шести часов, используется один раз и исчезает при перезапуске MCP.

## Конспект и схемы

`src/notebook.mjs` записывает выбранные учебные события в Markdown и не позволяет выйти за пределы workspace. Полная беседа автоматически не копируется.

`src/diagrams.mjs` подготавливает блоки Mermaid и обычные текстовые схемы. Они показываются прямо в разговоре и при необходимости добавляются в Markdown-конспект. Отдельный файл открывать не нужно.

## Что сохраняется

Сохраняются skills, инструкции клиента, конспекты, материалы, MCP-регистрация Codex и учебное состояние в `.concept-loom/sessions/`. В состоянии находятся цель, маршрут, закреплённые связи, пробелы и точный следующий шаг.

Не сохраняются незавершённые вопросы, вся переписка и расписание повторений.

## Ограничения

- Отдельного UI нет — используется выбранный клиент.
- Свободные объяснения оценивает модель.
- Поиск зависит от инструментов и разрешений клиента.
- Повторения не запускаются автоматически.
- Skill направляет модель, но не гарантирует идеальное соблюдение.
